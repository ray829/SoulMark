# md-reader 界面与交互优化规划

> 版本：v1 · 日期：2026-08-01
> 范围：基于现有 Tauri 2 + React 19 + Milkdown 的 Markdown 编辑器，做界面与交互的增量优化
> 原则：**延续而非推翻**现有极简设计语言，所有增强基于现有 token 与组件结构增量演进

---

## 0. 设计基线（必须延续）

现有语言是好的，优化应保持一致：

- **设计 token 体系**（`src/App.css:1-47`）：背景/边框/文字三层语义、中性蓝强调色 `--accent: #2563eb`、圆角 `--radius: 6px`、动画曲线 `cubic-bezier(0.4, 0, 0.2, 1)`。
- **极简 WYSIWYG 排版**（`src/styles/editor.css`）：标题下划线、自定义任务勾选、代码块线框，符合"阅读器"定位。
- **工程细节**：`prefers-reduced-motion` 兜底、滚动条精修、右键菜单防溢出、dirty ref 防帧滞后、Overlay 自定义标题栏。

核心问题不是"设计不好"，而是**功能太薄**——只覆盖了"最小可用"，离"好用的日常工具"有距离。

## 1. 实施批次总览

按"先补体验缺口，再提能力"的顺序，分三批：

| 批次 | 主题 | 目标 | 任务 |
|---|---|---|---|
| 第一批 | 体验止血 | 让"日常可用" | T1 欢迎页 · T2 暗色模式 · T3 自动保存 · T4 最近文件 · T5 拖拽打开 |
| 第二批 | 能力提升 | 让"写长文舒服" | T6 文档大纲 · T7 底部状态栏/字数统计 · T8 代码高亮 · T9 快捷键体系 |
| 第三批 | 结构升级 | 让"能管理多文档" | T10 多 Tab · T11 全局/文档搜索 · T12 图片粘贴插入 · T13 交互/视觉打磨 |

每批可独立交付、独立验证。建议每批结束后打 tag。

## 2. 第一批：体验止血

### T1 欢迎页 / 空状态主区域

**问题**：关闭文件后 `currentPath === null`，编辑区只剩空白 Milkdown（`src/App.tsx:153-170`），用户面对白屏不知所措。侧栏空状态引导逻辑（`src/components/Sidebar.tsx:470-490`）在 `rootDir` 为空时才出现，主区域没有对应引导。

**方案**：当 `currentPath === null && !dirty` 时，在 `.editor-wrap` 内渲染欢迎页。

- 顶部：应用名 + 简短 slogan
- 中部：三个主入口按钮（打开文件夹 / 打开文件 / 新建）
- 下半：最近文件列表（依赖 T4）+ 快捷键速查卡（Cmd+S/O/N/F 等）
- 视觉：48–56px 品牌图形，渐淡处理

**涉及文件**：
- 新增 `src/components/Welcome.tsx`
- 修改 `src/App.tsx`：条件渲染 Welcome 替代空 Milkdown
- 修改 `src/App.css`：`.welcome-*` 样式类

**验收**：
- [ ] 无文件且有未保存改动时不显示欢迎页（保持编辑器内容）
- [ ] 无文件且无改动时显示欢迎页
- [ ] 三个入口按钮分别触发 openFolder/openFile/newFile
- [ ] 焦点可被键盘 Tab 遍历，Enter 触发

### T2 暗色模式

**问题**：token 变量只定义了一套（`src/App.css:2-47`），长时间阅读/夜间写作体验差。

**方案**：
1. 将现有 `:root` token 抽成 `[data-theme="light"]`，新增 `[data-theme="dark"]`：
   - 背景：`--bg: #1a1a1a`、`--sidebar-bg: #161616`、`--surface: #242424`
   - 文字：`--text: #e8e8e8`、`--text-secondary: #999`、`--text-tertiary: #666`
   - 边框：`--border: #2e2e2e`、`--border-hover: #404040`
   - 强调色保持 `#2563eb`（或暗色下略提亮至 `#3b82f6`）
   - 交互态透明度相应调整
2. 启动时读 `prefers-color-scheme`，默认跟随系统。
3. 标题栏左侧加主题切换按钮（sun/moon 图标），状态持久化。
4. Milkdown 编辑器侧：`@milkdown/theme-nord` 已支持暗色，确认 `editor.css` 内所有 `var(--*)` 在暗色下表现正常，无硬编码颜色。

**涉及文件**：
- 修改 `src/App.css`：重构成双套 token + `[data-theme]` 选择器
- 新增 `src/hooks/useTheme.ts`：管理主题状态 + 持久化 + 系统偏好监听
- 修改 `src/App.tsx`：挂载 `data-theme` 到 `document.documentElement`，加切换按钮

**验收**：
- [ ] 浅色/暗色切换无闪烁（提前设置 data-theme 再渲染）
- [ ] 切换后所有区域颜色正确（侧栏、编辑器、模态框、右键菜单、滚动条）
- [ ] 默认跟随系统，手动切换后记住选择
- [ ] `prefers-color-scheme` 变化时同步（未手动覆盖时）

### T3 自动保存

**问题**：仅手动 Cmd+S（`src/App.tsx:61-80`），崩溃/误关即丢失。

**方案**：
1. dirty 状态变化后，debounce 1500ms 自动写盘（复用 `saveFile` 逻辑）。
2. 有 `currentPath` 才自动保存；无路径（新建未保存）仍需手动 Cmd+S 触发 save dialog。
3. 标题栏显示保存状态微文案：`保存中…` → `已保存`（2s 后淡出）。
4. 保留 Cmd+S 作为"立即保存"（绕过 debounce，直接写盘 + 反馈）。

**涉及文件**：
- 修改 `src/hooks/useFile.ts`：新增 `autoSave` effect + `saveStatus` 状态
- 修改 `src/App.tsx`：标题栏展示 `saveStatus`

**验收**：
- [ ] 编辑后 1.5s 自动落盘，关闭再打开内容不丢
- [ ] Cmd+S 立即保存并显示反馈
- [ ] 无路径文件不触发自动保存（避免弹 save dialog）
- [ ] 保存失败有错误提示（复用 `showError`）

### T4 最近文件 + 根目录持久化

**问题**：每次重启都要重新打开文件夹，"每次重新开始"。

**方案**：
1. 引入 `@tauri-apps/plugin-store`（或自写一个 JSON 持久化 command）。
2. 记录：
   - 最近打开的文件路径（去重，上限 10 条）
   - 上次的 `rootDir`
3. 启动时恢复 `rootDir`，欢迎页（T1）展示最近文件列表。
4. `openByPath` 成功后写入最近列表；`deletePath` 后从列表移除。

**涉及文件**：
- 新增 `src-tauri/src/store.rs`：或在 `lib.rs` 加 command 读写配置文件（`~/.config/md-reader/state.json`）
- 新增 `src/hooks/useRecents.ts`
- 修改 `src/hooks/useFile.ts`：openByPath/deletePath/renamePath 时维护最近列表
- 修改 `src/components/Welcome.tsx`（T1）：渲染最近文件

**验收**：
- [ ] 重启应用自动恢复上次 rootDir 与文件树
- [ ] 欢迎页显示最近文件，点击直接打开
- [ ] 删除文件后从最近列表移除
- [ ] 最近列表上限 10，超出淘汰最旧

### T5 拖拽打开

**问题**：文件管理器拖文件进来打不开，违反桌面应用直觉。

**方案**：
1. `.app` 根容器挂 `onDrop`/`onDragOver`：
   - 单文件 → `openByPath`
   - 文件夹 → `openFolder`（设为 rootDir）
   - 多文件 → 打开第一个
2. Tauri 拖放：确认 capabilities 已允许 `core:event:default` 或处理 `onDragDropEvent`。
3. 拖拽时给 `.app` 加 `.dragging` 高亮态（半透明蓝色覆盖层）。

**涉及文件**：
- 修改 `src/App.tsx`：拖拽事件处理
- 修改 `src-tauri/capabilities/default.json`：确认/补充拖放权限
- 修改 `src/App.css`：`.app.dragging` 样式

**验收**：
- [ ] 拖入 .md 文件直接打开
- [ ] 拖入文件夹设为 rootDir
- [ ] 有未保存改动时弹确认（复用 openByPath 的确认逻辑）
- [ ] 拖拽过程有视觉反馈

## 4. 第三批：结构升级

### T10 多 Tab 标签页

**问题**：单文件模型，切换文件要丢弃当前（`src/hooks/useFile.ts:60-81`）。

**方案**：
1. 状态结构从 `{currentPath, dirty}` 升级为 `tabs: Tab[]` + `activeTabId`。
2. 每个 Tab 独立持有 `{id, path, dirty, markdown, scrollTop, cursor}`。
3. Milkdown 实例复用：切换 Tab 时 `replaceAll(markdown)` + 恢复 scrollTop/cursor。
4. Tab 栏放在 `.editor-header` 上方或整合进标题栏。
5. Tab 右键：关闭/关闭其他/关闭右侧/在新窗口打开。
6. 保留单 Tab 兼容（视为 tabs.length === 1）。

**涉及文件**：
- 重构 `src/hooks/useFile.ts` → `src/hooks/useTabs.ts`
- 新增 `src/components/Tabs.tsx`
- 修改 `src/App.tsx`：布局与状态接 tabs
- 修改 `src/styles/editor.css` / `src/App.css`

**风险**：改动最大，建议作为独立分支开发；Markdown 内容切换需处理 Milkdown listener 误触 dirty（用 flush=true 已规避，见 `src/components/Editor.tsx:71`）。

**验收**：
- [ ] 多文件同时打开，Tab 切换内容不丢
- [ ] 每个 Tab 独立 dirty 标记
- [ ] 关闭有未保存 Tab 时确认
- [ ] 切换 Tab 恢复滚动位置与光标

### T11 全局 / 文档内搜索

**问题**：无搜索能力。

**方案**：
- **文档内**（Cmd+F）：编辑器顶部浮搜索栏，输入后 ProseMirror 内高亮匹配，上下跳转。
- **全局**（Cmd+Shift+F）：跨 rootDir 文件 grep。

**全局搜索实现**：
1. Rust 侧加 `search_in_dir(dir, query)` command，递归读 .md 文件，按行返回匹配结果 `{path, line, text, matches}`。
2. 前端渲染结果列表，点击跳转到文件对应行（依赖 T10 多 Tab 或直接 openByPath + 滚动）。

**涉及文件**：
- 修改 `src-tauri/src/lib.rs`：新增 search command
- 修改 `src-tauri/capabilities/default.json`：command 权限
- 新增 `src/components/SearchPanel.tsx`
- 修改 `src/App.tsx`：搜索栏浮层

**验收**：
- [ ] 文档内搜索高亮 + 上下跳转
- [ ] 全局搜索列出所有命中文件/行
- [ ] 点击结果跳转到对应文件对应位置
- [ ] 大量文件时性能可接受（异步 + 分页）

## 6. 风险与注意事项
